Three panes, because an agent does three things at once

Queue on the left so nothing is missed, conversation in the middle, customer context on the right so the agent never leaves the thread to look something up. The unread count and the green presence pip are the two things scanned most often, so they sit at the left edge of each row where the eye lands first.

What makes this a desktop app rather than a website

The tray badge in the title bar, a global hotkey to bring the window forward, native notifications, and closing the window leaving the app running in the tray. Those arrive in slice 6 — but the layout assumes them now so we’re not retrofitting a menu bar later.

Deliberately the same conversation

Both screens show TKT-2041 at 09:17. That is the comparison: identical data, identical websocket, three genuinely different runtimes. Where they differ — a notification banner on iOS, a URL bar on the web, a tray badge on desktop — they differ because the platform differs, not because we drew them differently.

Two auth modes, visible in the frames

The browser carries an httpOnly session cookie. The phone carries a Sanctum token from the Keychain as Authorization: Bearer. Both hit the same /broadcasting/auth endpoint and both are checked by the same TicketPolicy.

The states that actually get designed

Every screen answers all five before it ships
Empty No tickets yet “Nothing open. Start a ticket and we’ll reply within the hour.” With the action right there, not a shrug.
Loading Skeleton rows Three ghost rows at the real row height, so nothing shifts when data lands. Nothing at all under 200ms — a spinner that blinks reads as a bug.
Disconnected Reconnecting… A thin bar, not a modal. Composer stays usable; messages queue and send on reconnect. This is the state mobile spends real time in.
Send failed Retry, inline Message stays on screen greyed with a Retry beside it. Never silently dropped, never a toast that scrolls away unread.
Forbidden Not your ticket Policy denies both the HTTP read and the channel subscription. The client never sees the subject line, only that it cannot be opened.
